## 交付定位

学生将自己对计算机的兴趣追溯到《刀剑神域》。这为课程带来了一个具体问题：
在虚拟世界出现失败之后，人们为什么仍然继续建造这些世界，并在其中生活？
历史脉络可以把技术解释、日常关系和制度冲突联系起来。系列作品梗概会讲述
发生了什么；每个教学周还必须让学生运用来源材料，解释某种后果，或质疑一种解读。

首次评审使用同一份课程大纲，比较两种首页方案。在学生评审代表性教学单元之前，
这门课程仍是一项提案。公开网站尚未完成。评审页面已明确标记，且未列入导航；
现有起始模板页面不能作为课程内容已经完成的证据。

| [第 5 周：验证](https://comp.anu.edu.au/courses/comp4020-agentic-coding-studio/lectures/week-5/) | 检查实际运行证据，并将观察到的行为缺陷转化为恰当的回归检查。键盘操作、截图和控制台会揭示不同故障。 |
| [第 6 周：实践证据](https://comp.anu.edu.au/courses/comp4020-agentic-coding-studio/lectures/week-6/) | 通过历史记录追溯决策，随后保留有用的纠正，删去过时规则。最终 A2 过程陈述应把课程设计选择与写入规则的约束，以及有意识的人工判断联系起来。 |

我们对这些思路的延伸针对本项目：比较采用相同内容的设计方案，
独立检查评估器，保留改编版本层面的来源追溯，并通过真实人工评审
校准编辑与视觉判断。这是一项工作流程提案，不是经过测量、能够证明
它超越所有课堂实践的结论。

### 仍然相关的早期实验

现有[结果摘要](../harness-research/results-summary.json)记录了 18 次计分试验：
先进行了六组原版与 v2 的配对试验，随后进行了三组原版与最终 v3 的配对试验。
所有试验均通过其自动规则检查器。这并不意味着这 18 次结果都在语义层面完全正确，
也不意味着对 v3 完整重跑了六个案例、完成了 Claude 与 Codex 的比较，或获得了普遍的速度提升。独立评审发现，生成的
幻灯片链接正则表达式存在误报模式；试点期间还需要纠正评估器的范围。

修订版 [AGENTS.md 研究](https://arxiv.org/html/2602.11988v2)和
[效率研究](https://arxiv.org/html/2601.20404v2)已在那里分析。
它们没有确立一种最佳指令长度、上下文压缩比例或智能体数量。实际决策是保留
当前简洁的 harness，并作出幅度小、有依据的更改。用户要求查看的
[实践者仓库](https://github.com/shanraisshan/claude-code-best-practice/tree/b70072cc2fed48b710ddb555b66c3d0ad7c40641)
是一个思路索引，不是权限或设置预设。

## 文字审阅

检查空泛承诺、抽象赞美、重复的章节节奏、模糊的行动主体、缺乏依据的确定语气、
冗余免责声明，以及只是重复开头的结论。无论文字由人还是模型写成，
这些都是编辑问题。应保留会影响来源解读或实际决策的限定说明。

对每个周次页面都要问：发生了什么、哪一方的叙述支持它、要探讨什么问题，
以及学生接下来要做什么？在简要交代虚构前提后，保持历史叙述的语气。
不要反复向学生说明实现细节。在 Full-Dive、AR 和人工生命这些概念
能够帮助解释事件之处，解释它们。避免用泛泛的技术风险警告
取代课程特有的关注点。

后续将进行配对编辑比较，在保持证据和预期含义不变的前提下，
比较抽象开头与具体开头。只有真实用户回应才计入理解情况的证据。
模型意见将标为编辑评审。

## 比较方案：Gate 1

问题：首页应以档案式叙述开场，还是直接提供课程导览？A 与 B 使用相同的
课程大纲、考核安排和来源集合。两者都保留院校身份。信息顺序与构图有所不同；
这是配对设计比较，不是控制单一变量的因果实验。

检查任务：

1. 识别课程、面向人群和核心问题。
2. 找到讨论 Ordinal Scale 的周次及其历史问题。
3. 找到展览的分值权重，以及是否要求编程。
4. 找到来源与故事连续性的边界，并在 A、B 之间导航。

检查桌面与移动布局、标题、焦点、导航、溢出和控制台。
在 Gate 1 评审记录中记录实际观察与改进。随后由用户判断吸引力与清晰度。
不会报告虚构的用时、参与者数量、偏好或统计显著性。

### 评估器探针，9 月 27 日

一次只读复现比较了当前讲义链接正则表达式与 linkedom
（主题已经安装的解析器）。无效片段
`<a title="Use href='/comp4020-ass2-Naaeeen/decks/week-01/'">Slides</a>`
产生了一次正则匹配，但带有 href 的实际链接锚点数量为零。这证实了早期研究
发现的盲点仍存在于当前 spec 实现中。探针未修改任何网站内容。
在代表性教学单元依赖幻灯片链接断言之前，先纠正解析器并进行回归测试。
没有证据表明有效的起始模板幻灯片链接本身已经损坏。

### Gate 1 结果

[评审记录](../planning/gate-1-review.md)记录了最初比较、实际浏览器缺陷、
两次改进，以及对独立评审意见的核对处理。修复移动端片段导航时，
我们查阅了 [W3C 披露组件示例](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/)。
其普通导航语义以及 Escape／焦点行为，为一个小型页面局部处理器提供了依据。
该示例是指导材料；通过我们的针对性案例不能证明获得辅助技术认证。

最初的手机端构图让课程导览出现得过晚。将课程前提和先修要求移到共享开头后，
两种方案都能在首屏呈现它们。我们保留了两个有效选项，交由学生判断。
尚未收集人工 A/B 结果，也没有声称全部课程已经完成。

### 动画与访问决策

控件设计参考了 [W3C 的暂停／停止／隐藏指导](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)

一个 canvas、设备像素比上限 1.5，并在隐藏、离屏或暂停时停止场景循环。
这些是我们要检查的目标，不是作业要求，也不是测量结果。

### 评审证据与工作方法

之前关于 OpenAI 评估和 Anthropic 委派／上下文的发现，仍为本阶段提供指导：限定文件归属、针对任务进行检查，以及由主代理验证评审意见。我们复用了这些发现，而不是宣布一套新的通用代理配方。我们不声称更多代理、更多软件包或更多动画必然带来更好的课程。

Gate 3 第一次完整检查的类型诊断为零，但出现了真实的无障碍失败：图谱内部存在名称重复的地标区域。随后，主代理的浏览器检查复现了评审代理指出的三个问题：粘性工具栏被遮挡、进入控件 URL 时世界选择状态丢失，以及控制器从原生跳过链接夺走焦点。当前的 [MDN 定位文档](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/position)、[滚动外边距文档](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scroll-margin-top)和 [GSAP 上下文生命周期文档](https://gsap.com/docs/v3/GSAP/gsap.context()/)支持有针对性的修复；决定是否接受的是最终浏览器结果，而不只是建议本身。结果记录在 Gate 3 评审记录中。

内容评审还暴露了缺少提交作业和反馈安排的问题。课程现在明确了虚构的当面提交／答疑安排、与课程负责人商定的无障碍替代方式，以及在下一次考核需要反馈之前提供反馈的时间。这是我们的课程设计选择；我们没有声称存在可用的外部提交服务。展览的形式也已统一为幻灯片、文档或自包含网页。

针对已经观察到的范围偏移，代理工作规范增加了一条简短的定期要求审计规则。详细审计发现保留在链接记录中。PROCESS.md 仍是学生之后要撰写的自述；这些笔记提供可验证事件，而不是编造个人经历或人的偏好。


最后一次 API 检查显示，通用集成默认生成的是空的 `learningOutcomes` 数组。计划中已经包含四个学习目标，因此首页现在从现有 course-outline 数据中发布这些目标。最初试图把它们加入 `courseMeta` 的尝试失败了：起始模板在 `src/course-config.ts` 中定义的本地严格模式，其字段集合比通用集成更窄。主代理检查了这一实际模式，并恢复了未更改的课程记录；没有放宽任何验证、固定 API 契约或构建集成。被否决的候选方案记录在 `/tmp/a2-gate3-candidate-xy1flfse.log`。

原生跳过链接受到干扰，也构成了在 CLAUDE.md 现有导航检查规则中补充一句简短说明的理由。受控 DOM 评审通过后，又进行了实际浏览器检查：使用跳过链接后，下一次 Tab 会进入主要内容；世界／视图状态能够通过控件链接和浏览器历史导航保留下来。模拟评审并未证明粘性定位的几何表现或原生 BFCache 行为正确。


## Gate 4 研究与决策——2026 年 9 月 28 日

学生同意继续推进，随后提出了三项相互关联的修正：展示讲座幻灯片，让第一步操作和每周学习安排立即可见，以及面向完全不了解背景的新生，从 2035 年的视角将 SAO 作为历史事件来教授。后续指导又提出，应提供超越导航菜单本身的学习路径。这些是用户实际提出的要求，不是模型评审编造的发现。

[实施前计划](../planning/gate-4-plan.md)记录了实时作业说明、未发生变化的上游 ecd1d71228e40105310fcb25e1bcf00cc5ed5284、文件归属、来源模式和验收检查。主代理记录了原有的 1920×1080 讲义目录：四张卡片，没有直接指向幻灯片的链接，也没有内嵌幻灯片。它还为讲义标出了日期，却未解释授课形式。元数据／文案审计发现了一项界面没有呈现的跨周安排：第 9 周复用了第 2 周讲义。

### 历史视角改变后，来源模式也必须随之改变

独立评审确认，仅替换术语是不够的。旧版第 2 周考核要求使用宣传材料原文并分析改编差异；幻灯片则将 2021 年的媒体发布与 2022 年的事件并列比较。这些任务实际进行的是媒体分析，而不是学生想要的历史课程。

必读材料现正被修订为内容充实、具有稳定段落定位的课程编写案例叙述。正文以历史视角处理人物和事件。来源说明保留真实的出版方、作品、日期、改编关系和教学设定。这些叙述不会被错误标注为日记或独立目击证言。考核要求学生使用站内段落，比较编写侧重点和有证据支持的解释。事件时间线取代了原来的作品制作日期练习。叙事背景先定义陌生人物和系统，再要求没有相关背景的学生进行分析。

主代理重新核查了游戏上线及首月的来源，以及此前已经检查过的案例来源。官方 [Fairy Dance 简介](https://www.swordart-onlineusa.com/fairy_dance/intro/)将文字放在一张没有可用替代文本的图片中。网页文本提取失败后，主代理在浏览器中查看了原图。它支持以下内容：Kirito 在与 Kayaba/Heathcliff 交战后返回，以及包括 Asuna 在内的 300 人仍未恢复意识。[2024 年 11 月的剧集梗概](https://www.swordart-onlineusa.com/aincrad/story/?no=14)为 Aincrad 后期的一连串事件标明了时间，但仅凭它不能得出结束的确切日期。导引材料采用有证据支持的相对时间顺序，也不声称所有 100 层都已通关。

### 内嵌真实幻灯片

执行代理检查了 Astromotion 0.23.0 和 Reveal 6.0.1，而不是想当然地假设框架层面提供了相应配置。Astromotion 将默认值写死；Reveal 在运行时合并查询参数设置，并提供有文档说明的 [postMessage 接口](https://revealjs.com/postmessage/)。主代理阅读了这一一手 API 文档，以及 [W3C 框架标题指导](https://www.w3.org/WAI/WCAG22/Techniques/html/H64)、[轮播控件模式](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/)和[重排说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。原型使用真实的本地幻灯片，提供明确的外部控件、消息来源域与 iframe 身份检查、就绪响应、始终保留的阅读／演示链接，以及足够高的手机显示框。原有幻灯片在窄屏／短屏下会重排，因此浅矮的 16:9 手机显示框并不适合。仅有 load 事件，不被算作播放器已经可用。

幻灯片自身定义的内嵌样式类，会在查看器内隐藏“每个标签页首次出现”的提示，因为可见控件已经解释了导航方式。没有改动第三方组件的导出或自动化标记。原生辅助逻辑仍会消耗按路径记录的已看过提示标记；这一实现限制保留下来，交由浏览器／人工评审考虑。这不能作为已经测试过普通用户首次看到提示的证据。没有增加新的依赖或付费 API。

### 正在进行的验证方法

各执行代理的工作范围受限，分别负责 UI、幻灯片、来源和教学文案。主代理负责集成与独立验证。新的学习导航检查在未经改动的 Gate 3 构建上运行，得到四项真实失败和一项通过。它们覆盖各周准备材料的路径／顺序、准备时间预算是否匹配、第 9 周的跨周讲义安排，以及课堂时间地点是否一致。它们不测量清晰度或教学质量。最终浏览器结果和提交链接将在集成后记录，而不是在这里预先断言。

### 首轮浏览器走查后的组织结构改进

学生要求让重要页面保持可见，随后又明确要求在仓促发布之前认真完成组织结构。因此，设计现在将四个主要入口——“从这里开始”“每周计划”“世界图谱”“资料库”——与单独的学习资料栏——“讲义与幻灯片”“案例资料”“考核”“人员与帮助”——配合使用。资料栏是静态的，首次使用的起始页省略了它，以保留一个明确的第一步操作。“资料库”解释资源用途，但不再是进入重要材料的唯一路径。

主代理阅读了 [NN/g 对信息架构与导航的区分](https://www.nngroup.com/articles/ia-vs-navigation/)：除了可见菜单，还需要设计页面分组、标签和关系。学期学习路线，以及各周按课前／共同学习／课后组织的学习档案，提供了这些关系。我们没有声称开展了参与者研究，也没有声称测得了学习收益。

在 390x844 视口下，最初版本的周次选择器位于 y=1384，在完整的学习节奏说明下方。现在，选择项放在“每周计划”页头中，使用原生锚点和现有的键盘焦点处理。经过视觉评审，学习资料栏链接标签的字号从 12px 增大到了 14px。

学生的截图还显示，箭头与编号圆圈发生了接触。紧凑版本的网格间距是 28px，却保留了 30px 的外部箭头偏移；主代理在浏览器中确认了这一几何关系。依据 [MDN gap](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/gap) 描述的实际间距模型，连接符现在居中放置于共享间隙中，采用固定宽度，并为手机单独设置纵向样式。视觉 CSS 缺陷需要通过实际渲染的几何关系验证，而不是靠检查是否写入某个特定 CSS 字符串的测试。

## Gate 5 证据草拟——2026 年 9 月 28 日

主代理重新阅读了 [AI 使用政策](https://comp.anu.edu.au/courses/comp4020-agentic-coding-studio/topics/ai-use-and-integrity/)和[考核指导](https://comp.anu.edu.au/courses/comp4020-agentic-coding-studio/topics/assessment/)。政策允许在由人承担责任的前提下使用 AI 起草，禁止虚假的过程自述，并要求说明对早期工作的复用。作业要求中的 400–600 词是指导性建议，不是机械扣分的阈值。

学生要求先行准备，并提供中文审阅文档。草稿仅使用了学生本人提供的 SAO 动机、认可的课程方向、明确的研究和验证要求、关于范围的提问，以及 UI 反馈，并将它们与真实提交对应。代理进行的浏览器工作被明确归属于代理。对 Crit 5 的复用也被列明。十八次代理工作规范试运行，没有被误报为十八组配对试验，也没有被说成普遍成功。生成输出检查证明的是结构一致性，不是真实的学习耗时、理解程度或人的偏好。比较部分的引用现在既包含计划／工作规范提交，也包含其后续实现。

一次有限范围的独立评审没有发现实质性的工作归属、引用或翻译问题。主代理核查了实际差异，以及两份译文中的 URL、命令和重要路径。移除 Markdown 链接目标后，英文草稿按空白字符分词共 512 词；证据检查能够解析七个提交 ID。已配置的文风检索没有返回适用的参考样例，因此草稿遵循学生明确表达的平实写作偏好，不声称匹配了检索到的文风。该自述仍需由人批准。
