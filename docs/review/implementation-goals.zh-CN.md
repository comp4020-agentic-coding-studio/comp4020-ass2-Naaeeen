## 动效、交互与额外工具

研究教育网站之外的优秀案例，包括产品叙事、互动展览、创意作品集、视觉新闻报道及其他出色的网站。亲自检查真实交互；能够找到时，也阅读作者对实现方法的解释或源代码。明确指出某个可以迁移的具体技巧，并说明它在本课程中的作用。学习其方法，不要照搬品牌素材，也不要只因为知名网站用了某种特效就加入它。

只要与课程固定平台兼容，可以使用额外的浏览器 API、npm 包、组件和外部 API。采用之前，根据当前在线 brief、上游模板和已安装依赖核实兼容性。保留 Slop 身份标识与配色、Astro 集成、集合键名及生成的 API。根据希望达到的体验选择工具，不要只受限于已经安装了什么。记录某项依赖为什么有帮助、当前版本及许可证、运行与构建成本，以及实际结果。普通且适合本项目的依赖已经获得授权；付费服务、新账号、凭据变更或无关集成，需要另外取得明确范围的授权。绝不能把秘密凭据放入客户端代码包。

目标是做出有表现力的历史展览：令人记住的场景、有意义的空间层次、节奏合适的过渡，以及能鼓励探索的即时反馈。动画应把事件、资料或课程章节与它的意义联系起来。同时，课程导览、课前准备、考核和导航仍应容易阅读和访问。

第一节点比较了静态设计方向，以及包含程序化生成的 3D 场景和章节浏览器的方案，并为其提供对应的静态替代呈现。学生认可了修改后 C 方案的大方向。把这套动效风格延续到课程中，同时在浏览器里验证导览和阅读体验；不要重新开始已经完成的比较。

学生认为第一版 C 模型不像艾恩葛朗特，动效也不够。第二版修订通过查看官方视觉参考并评估现有同人模型来改进，而不是凭空设计一座无关的浮空城。保留之前的截图作为比较证据。对照原作动画参考，比较连续收窄的主体、密集的楼层带、底部结构、放射状桥梁、材质和视觉尺度。提供清楚可辨、与其对应的回退图像。

学生还明确要求更多 2D/3D 动画，以及更大的运动幅度：正常模式下，云层移动、镜头运动和章节图形应明显可感，而不只是细小的淡入淡出和位移。加入与章节关联的 2D 插图，以及随阅读逐步展开的时间线。文字和控件的可点击区域应保持稳定，并配备下文规定的动效控制。

学生允许在这个私人工作预览中使用合适的现有模型和图片。记录创作者、来源、许可证，以及它是被实际使用还是仅作参考。本轮修订不得改变仓库可见性，也不得发布网站。最终作业要求的公开 Pages 网站仍是独立的发布任务。

动效验收条件：

- 内容与导航直接呈现，不必等待开场动画、远程 API 或 canvas。
- 普通滚动、键盘导航和触屏阅读保持可用。
- 尊重“减少动态效果”设置，包括页面打开期间偏好的变化；为持续但非必要的运动提供清楚的暂停或停止控制。
- 某项增强功能失败或不可用时，仍保留有用的 HTML 内容和图像。
- 场景移出屏幕或标签页隐藏时暂停场景运算；扩展这种实现方式前，检查桌面和手机上的窗口调整行为，以及实际下载和运行成本。
- 在两个评分窗口尺寸下，验证动画、选择状态、焦点和静态替代呈现，并取得独立审查与真实的人类反馈。

这些条件补充下文的五个节点。节点 2 确立所选动效风格如何支持一个真实教学单元；节点 4 在全站范围检查它。在追求明显更好的视觉体验时，仍要把截止时间内完成一门完整、连贯的课程作为工作重点。

## 节点 1：课程结构与视觉方向

## 节点 2：完整的代表性教学单元

收到节点 1 反馈后，交付一个完整可用的教学周、对应 lecture 页面和真实幻灯片、一项资料分析活动，以及一份有代表性的考核说明。用一个资料充分的案例展示预期深度。针对不熟悉 SAO 的学生，检查资料身份、连续性、准备负担和可访问性。

验收条件：学生可以顺利沿着“首页 → 教学周 → 准备或活动 → lecture/幻灯片 → 考核”行动，不遇到坏链接或未解释的前置条件。幻灯片文字在两个评分窗口中都放得下且清楚可读；讲义或等效阅读页面保证手机访问。只读独立审查的意见已核实并处理。

**真人审阅：**细节深度、教学语气、资料选择，以及这门课是否让人想选。记录真实回应后，再推广这种方式。

## 节点 3：完整课程与信息架构

收到节点 2 反馈后，完成十二周，使用一致的 2035 年日期、不同的问题、可行的准备和活动，并建立周与周之间的联系。完成三项考核（20/30/50）、评分标准和截止时间、有意义的 lecture 页面、承诺提供的幻灯片、人员、政策、资料，以及有用的事件时间线。区分历史事件的时间顺序与课程教学时间表。

验收条件：所有必需页面都有实际编写的课程内容；不存在未标明的虚构资料；资料比较明确识别对应改编版本；考核权重合计 100；教学周覆盖 1–12；日期在教学期间内；分配的代码数字保持不变；至少一份 lecture 链接到真实构建出来的幻灯片。实质性地替换 starter 内容。使用生成的 API 和构建输出验证可机械检查的要求。

**真人审阅：**完整性、课程推进、历史论证与计算机解释及日常生活之间的平衡，以及考核工作量。

## 节点 4：可用性、文字与媒体完善

收到节点 3 反馈后，审阅完整的学生使用过程，并对仍存在不确定性的重要方案进行比较，例如每周导航或资料呈现方式。保留有用的视觉功能，移除妨碍学习的效果。检查不相邻的教学周、每项考核、有代表性的幻灯片和时间线。

验收条件：检查 1920×1080 桌面窗口和 390×844 手机窗口；在适用时测试键盘操作、焦点可见性、窄屏换行、窗口调整和减少动态效果。使用现有浏览器工具检查控制台及错误，并检查慢速连接条件。工具无法复现某种条件时，记录这一验证缺口，不能声称已经通过。检查加载成本、图像替代内容和媒体来源。

**真人审阅：**实际使用完整网站、文字质量、可读性，以及最后的内容修正。人类反馈与自动化或模型审查是不同的证据。

## 工作循环与停止规则

1. 明确下一个可以观察到的结果，以及它的要求来自哪里。
2. 研究存在不确定性的决策；核对实际安装的代码，确认 API 行为。
3. 实现小而连贯的修改，保留无关工作。
4. 运行相关检查，查看真实输出；实质性修改需要独立审查。核实审查者和测试判定逻辑，不要只接受一个结论标签。
